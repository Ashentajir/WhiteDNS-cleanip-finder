# WhiteDNS 1.3.8

WhiteDNS 1.3.8 improves DNS tunnel resolver discovery on desktop and Android by validating each transport independently and accepting resolvers that have at least one genuinely usable tunnel path.

## Highlights

- Probes TXT forwarding on every selected DNS transport instead of relying on a single UDP result.
- Accepts a clean TCP/53 path when UDP/53 is poisoned, injected, stripped, or returns a truncated TXT response.
- Requires A-record integrity, recursion, and TXT passthrough on the same transport so evidence from a dirty path cannot validate another path.
- Requires EDNS0 for UDP tunneling while correctly allowing TCP, DoT, and DoH tunnel paths without it.
- Rejects resolver-wide NXDOMAIN hijacking while preserving per-transport poisoning evidence in reports.
- Uses one canonical pass rule for desktop results, Android results, nearby-IP expansion, and raw passed-resolver files.
- Reports the selected tunnel transport (`udp`, `tcp`, `dot`, or `doh`) in desktop and Android logs.

## Build artifacts

Desktop CI builds Windows amd64, Linux amd64/arm64, macOS amd64/arm64, and Termux arm64 binaries. Android CI builds signed ABI-specific and universal APKs plus a release AAB.

## Upgrade notes

No configuration migration is required. The DNS scan remains a transport-aware preflight; the optional DNSTT end-to-end test is still the definitive validation that a resolver carries real tunnel traffic.
